Set up home config using stow. Pi config (settings, keybindings, extensions,
skills, and the npm package manifest) lives in =dot-pi/agent/=. Create the Pi
agent directory
first so stow links individual files instead of folding =~/.pi= into the repo;
Pi's generated state (auth, sessions, model cache) stays outside dotfiles.
#+begin_src bash
mkdir -p ~/.pi/agent
cd ~/dotfiles && stow --dotfiles .
#+end_src

* quick-claude
A wrapper to launch ~claude~ in a popup that always resumes the same "quick"
session. Source of truth lives in =dot-local/bin/quick-claude= and is symlinked
into =~/.local/bin= (matching how =claude= and =poetry= are managed there).

Behavior: =~claude --permission-mode manual --model haiku=, then:
- If =~/.quick_claude_session= holds a session id, resume it with =--resume=.
- Otherwise start a fresh session under a generated =--session-id= and remember it
  in =~/.quick_claude_session=.

Delete =~/.quick_claude_session= to force a fresh session.

Binding (in =dot-tmux.conf=): =M-c= opens a popup running ~quick-claude~.

The symlink into =~/.local/bin= is managed by Stow; no manual linking is needed.

* update-zsh-plugins
Pulls the two zsh plugins that are sourced directly from =~/.zplug/repos= by
=dot-zshrc= (zsh-vi-mode and powerlevel10k), and recompiles the powerlevel10k
byte-code cache. zplug itself is no longer loaded at shell startup, so run this
manually to update them:
#+begin_src bash
update-zsh-plugins
#+end_src

Like =quick-claude=, the source of truth is in =dot-local/bin= and Stow links it
into =~/.local/bin=.

* rex config
Rex's config lives in =dot-config/rex/= (=init.lua=, =scrollback.lua= and
=cheatsheet.txt=). Stow links those files into =~/.config/rex/=; the directory
itself stays real so generated state (e.g. =last_session.debug.log= and
scrollback captures) remains outside the dotfiles repo.

* pi: opencode-go usage extension
Shows OpenCode Go rolling (5h), weekly and monthly usage from
=https://opencode.ai/inference/go/v1/usage=. The key is read from
=OPENCODE_API_KEY= or =~pi/agent/auth.json=.

Extensions under =dot-pi/agent/extensions= are linked into Pi's auto-discovered
extension directory by Stow; no manual linking is needed.

Commands:
- =/go-usage= shows the usage panel (=R= refreshes, =Esc= closes).
- =/go-usage refresh= bypasses the one-minute cache.
- =/go-usage status= toggles the compact footer status.

* pi: long-command-shell extension
Pins a scrollable, boxed terminal view above Pi's editor while an agent =bash=
tool call runs longer than a threshold. The box shows the command, elapsed time
and output, follows the tail by default, then clears when the command finishes.
Scroll with the mouse wheel or =alt+up=/=alt+down= (=alt+pageUp=,
=alt+pageDown=, =alt+home= and =alt+end= also work); scrolling up pauses
auto-follow. It observes tool execution events, so the built-in bash tool and
its rendering are unchanged.

Configure with =PI_LONG_SHELL_DELAY_MS= (default =2000=),
=PI_LONG_SHELL_LINES= (history kept for scrolling, default =200=) and
=PI_LONG_SHELL_BOX_HEIGHT= (defaults to =auto=: 30% of the terminal's rows,
clamped to 6-30, and recalculated when the window is resized; set a number for
a fixed height). At runtime, =/long-shell= shows settings, =/long-shell on|off=
toggles the box, =/long-shell height <n>= fixes the height live,
=/long-shell height auto= restores the 30% behaviour, and =/long-shell <ms>=
changes the delay.

* pi: commit-staged skill
Reviews the staged diff, drafts a commit message in the repository's existing
style, and asks for explicit approval before committing. It only commits what
is already staged: no =git add=, =-a=, amend, or push. Run =/skill:commit-staged=
(or ask Pi to commit the staged files); arguments are treated as requested
wording for the message. Skills in =dot-pi/agent/skills= are linked into
=~/.pi/agent/skills= by Stow, so no manual setup is needed.
